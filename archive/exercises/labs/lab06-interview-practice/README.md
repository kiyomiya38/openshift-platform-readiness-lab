# Lab 06: 面談回答練習

> [!IMPORTANT]
> **状態:** 演習資料: 準備済み / 本人実施: 未実施 / 実機証跡: なし


OpenShift 基盤案件の面談を想定し、現在地を正確に伝えながら、今後の本人レビュー・演習で確認した調査観点を短く説明する練習です。`questions.md` に自分の回答を書いてから `model-answers.md` と比較します。

## 学習目標

- 60 秒で経歴、現在地、強み、学習方針を説明できる。
- 商用経験、教材・検証経験、概要理解、未経験を明確に区別できる。
- OpenShift/Kubernetes/Virtualization/Airgap/Ansible の要点を結論から答えられる。
- 障害調査をコマンド列ではなく、層と仮説検証の流れで説明できる。
- AI 利用時の情報管理と人による最終確認を説明できる。

## 前提条件

- この Repository の概要、設計、障害調査、各 Lab を一度読む。
- 自分が実際に完了した Lab と未実施項目を一覧にする。
- 録音する場合は個人利用・保存先・削除時期を確認する（要確認）。

## 安全上の注意

- 実施していない商用構築、設計、障害対応を経験として話さない。
- 顧客名、実 host/IP、incident、個人名、契約情報を回答へ含めない。
- AI が作った回答を自分の経験として読まず、事実と一致する部分だけを使う。
- 製品仕様は版により変わるため、断定が必要な質問は「対象版の公式文書で要確認」とする。

## セットアップ

1. [questions.md](questions.md) を複製して `my-answers.md` を作る。
2. 各回答の先頭にレベルを付ける: `[商用経験]`、`[教材・検証]`、`[概要理解]`、`[未経験]`。
3. 60 秒回答は 180～260 日本語文字、技術質問は 30～60 秒を目安にする。
4. Timer と録音は任意。録音に実情報を含めない。

## Exercise 1: 1 分自己紹介

次の順で一つの文章にします。

1. 現在の中心業務
2. 既存の基礎（Linux、network、AWS、Docker、Kubernetes 等のうち事実だけ）
3. OpenShift に関して実際に行った教材・検証
4. 案件で貢献できる進め方
5. 未経験領域は確認・review を受けて進める姿勢

固有名詞を並べ過ぎず、聞き手が「任せられる範囲」と「支援が必要な範囲」を判断できる内容にします。

## Exercise 2: 現在地の説明

`questions.md` の Q02～Q05 に答えます。次の型を使います。

```text
結論: 商用経験の有無と現在のレベル
根拠: 実際に行った教材・検証・成果物
理解: 設計または調査で見る具体的な観点
境界: 未経験部分と、参画時の確認・review 方法
```

「できます」だけで終えず、逆に「未経験です」だけでも終えません。

## Exercise 3: 技術説明

Q06～Q14 を 45 秒以内で答えます。回答後、次を自己確認します。

- 最初の一文で質問に答えたか。
- Kubernetes と OpenShift、VM と Container、Mirror と Backup などを混同していないか。
- 設計で決める項目か、運用で確認する項目かを区別したか。
- 環境依存事項を断定していないか。

## Exercise 4: 障害調査の口頭説明

Q15～Q19 は、次の順で答えます。

```text
影響と対象確認
→ 全体正常性
→ 症状が見える層の get/describe/event/log
→ 依存先を一段ずつ確認
→ 事実と仮説を分ける
→ 変更承認・切戻しを決めて最小範囲で対応
→ 技術状態と業務疎通で復旧確認
```

コマンドを全部暗唱する必要はありません。最初に見る代表コマンドと、出力の何を見るかをセットにします。

## Exercise 5: AI ガバナンスと NG 表現

Q20～Q24 に答え、自分の回答から次を除きます。

- 商用経験がないのに「構築しました」「設計しました」「対応できます」
- 「AI に聞けば分かります」「多分」「何でもできます」
- 版、基盤、権限に依存する値の断定
- 顧客情報を AI へ入力することを前提にした説明

## 検証

一人または相手役と、質問をランダムに 10 問選んで模擬面談を行います。

| 観点 | 0 | 1 | 2 |
|---|---|---|---|
| 結論 | ない | 後半 | 冒頭で明確 |
| 経験境界 | 誤認を招く | 一部曖昧 | 商用/教材/概要を明示 |
| 具体性 | 抽象的 | 用語のみ | 観点・手順・成果物あり |
| 正確性 | 混同 | 一部要確認 | 版依存も明示 |
| 簡潔さ | 長すぎる | やや冗長 | 時間内 |
| 対応姿勢 | 精神論 | 確認するとだけ回答 | 公式文書/非本番/review を具体化 |

10 点以上を目標にし、[model-answers.md](model-answers.md) と比較します。モデル回答はそのまま暗記せず、自分が実際に行った内容へ削ります。
