# 証跡管理ガイド

## 目的

`evidence/` は、技術資料が存在することと、本人が理解・確認・実施したことを分けて管理する領域です。

このディレクトリを追加しただけでは学習証跡になりません。日付、対象、環境、実施内容、結果、判断、成果物を本人が記録し、必要なレビューを受けた時点で初めて証跡候補になります。

## 生成 AI 支援の扱い

リポジトリの技術資料初稿は、生成 AI の支援を利用して作成しています。AI 出力は、本人の技能、理解、操作経験を証明しません。

AI 支援を受けた項目は、次の条件をすべて満たすまで「未レビュー初稿」とします。

1. 本人が全文を確認し、不明点と修正点を記録した。
2. 対象バージョンの公式資料で主要な記述を確認した。
3. 実機確認が必要な内容は、安全な環境で実施して結果を残した。
4. 本人が資料を見ずに目的、手順、結果、制約を説明した。
5. 必要に応じて第三者レビューを受け、指摘と修正を残した。

## 状態ラベル

| ラベル | 意味 | 技能証明としての扱い |
| --- | --- | --- |
| 未レビュー初稿 | 文章・サンプルはあるが、詳細レビュー・裏付け前 | 使用しない |
| 本人レビュー済み | 本人が読み、疑問・修正を記録 | 理解完了とはしない |
| 公式資料確認済み | 対象版の一次資料で裏付けた | 知識の根拠候補 |
| 教材・検証済み | 本人が非商用環境で実施し、結果を記録 | 環境と制約を付けて説明可能 |
| 自己説明確認済み | 本人が自分の言葉で説明し、質問へ回答 | 概要理解の証跡候補 |
| 第三者レビュー済み | 他者の確認と指摘反映を記録 | 信頼性を補強 |
| 商用経験 | 実案件で責任範囲を持って実施 | このリポジトリのラボでは付与不可 |

## 証跡への昇格フロー

```text
未レビュー初稿
  → 本人レビュー
  → 公式資料確認
  → 実機検証（必要な項目）
  → 自己説明
  → 第三者レビュー（必要な項目）
  → 経験ラベルと提出可否を再判定
```

途中のゲートを飛ばした場合は、その理由と代替確認方法を記録します。実機環境がない場合は「概要理解」までに留め、検証済みとはしません。

## 証跡 ID

記録には次の形式で一意な ID を付けます。

```text
LR-YYYYMMDD-NN  # Learning Record
VR-YYYYMMDD-NN  # Verification Record
RV-YYYYMMDD-NN  # Review Record
```

関連する要求 ID、文書、ラボ、成果物から同じ証跡 ID へリンクします。

## 記録してよい内容

- 公開可能な検証環境の種類と製品バージョン
- 実行した一般的なコマンドと、機密情報を除いた結果
- 期待値、実測値、判断理由、失敗と修正
- 参照した公式資料のページ、確認日、対象バージョン
- 自己説明で答えられなかった質問と再学習内容
- 第三者レビューの指摘要約と修正内容

## 記録してはいけない内容

- 面談の生の発言、録音、文字起こし、個人名、組織名
- 顧客名、案件名、業界、システム名、非公開の構成・規模
- 実在する IP アドレス、ホスト名、ログ、メールアドレス、認証情報
- Token、Secret、秘密鍵、pull secret、kubeconfig
- 利用許可のない内部資料やスクリーンショット

必要な情報は架空値へ置き換え、マスキング後に秘密情報が残っていないことを確認します。

## 更新ルール

1. 予定は実績欄へ書かない。
2. 成功だけでなく、失敗、未解決事項、補助の有無を残す。
3. 「分かった」ではなく、説明または実測で確認する。
4. AI の回答を出典にせず、一次資料と実機結果を記録する。
5. 経験ラベルの変更理由を履歴へ残す。
6. 外部提出可否は [submission-readiness.md](submission-readiness.md) の全必須ゲート確認後に判定する。
