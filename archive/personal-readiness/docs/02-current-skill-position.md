# 現在地のスキル整理

## 結論

面談メモから確認できる強みは、インフラ研修教材の作成、学習・検証環境の構築、Linux・ネットワーク・AWS・Kubernetes の基礎を学習者向けに分解して説明してきたことです。一方、商用 OpenShift / Kubernetes の設計・構築・運用経験はありません。商用本番環境での障害対応経験もありません。

このリポジトリは、面談で求められた領域を確認するために準備された資料初稿です。`docs/00`〜`docs/27` の初回通読は済んでいますが、詳細レビューとラボ実施は完了していないため、内容を理解済み・再現済みとする証拠ではありません。過去の教材・検証経験と、今回これから行うレビュー・演習を明確に分けて扱います。

## 過去資料と照合する技術詳細

過去の棚卸し資料には、Kubernetes について `kubeadm`、Pod、Deployment、Service、Ingress、ConfigMap、Secret、`kubectl`、CNI、HAProxy、OpenShift について Project、Route、RBAC、SCC、Operator、`oc` が候補として記載されています。ただし、面談メモだけでは各項目の実施内容と到達範囲を独立に確認できません。提出前に過去教材・実行記録と照合し、確認できた項目だけを「教材・学習環境ベース」の経験として残します。

GitOps、Pipelines、Monitoring、Logging、OADP は、本リポジトリに解説初稿があり、初回通読まで行った状態です。詳細レビュー前は「教材・概要整理レベル」とも断定せず、「資料初稿・詳細未確認」と表示します。

## 強みを案件の行動へ変換する

### 教材作成経験

- 複雑な内容を前提、操作、期待結果、補足へ分解できる。
- 初学者が止まりやすい点を予測し、確認コマンドを添えられる。
- 実案件では、構築手順、試験仕様、運用手順の明瞭性へ転用できる。
- ただし、教材品質と本番変更の品質保証は同一ではない。承認、証跡、切り戻し、複数人レビューが加わる。

### 検証環境構築経験

- 前提条件を揃え、再現手順を残し、結果を比較できる。
- エラーを検索する前に、状態、イベント、ログ、依存先を確認する型を持てる。
- 実案件では、PoC、単体試験、不具合再現、手順リハーサルへ転用できる。
- ただし、性能、可用性、セキュリティ、サポート条件は検証規模だけで断定しない。

### 教材内のトラブル整理経験

- 過去に行ったのは、受講者がつまずきやすい点や質問の多い点を調べ、他の講師へ共有するための整理である。
- 顧客の商用環境で、障害影響を判断し、復旧や恒久対策に責任を持った経験ではない。
- 今回の障害ラボも未実施であり、実行結果が記録されるまでは調査技能の証拠として扱わない。

## 「操作できる」と「案件を進められる」の差

| 操作の理解 | 基盤案件で追加される責任 |
| --- | --- |
| YAML を apply できる | 変更理由、差分、権限、影響範囲、承認、切り戻しを示す |
| Pod を起動できる | リソース見積り、配置、可用性、セキュリティ、監視を設計する |
| Route を作れる | DNS、証明書、LB、Ingress Controller、公開範囲を調整する |
| ログを見られる | 時系列と仮説を管理し、証跡を残して適切にエスカレーションする |
| バックアップを取れる | RPO（許容するデータ損失）、RTO（復旧までの目標時間）、対象、保管、暗号化、復元試験、責任者を決める |

## 本人確認後に使える経験境界案

### OpenShift

> 商用環境での OpenShift 設計・構築・運用経験はありません。過去には CRC と Web 上の Sandbox を使い、Project、Route、Operator などを扱う入門教材を作成しました。SCC、RBAC、`oc` を含む具体的な到達範囲は、提出前に実施記録と記憶を照合します。このリポジトリは資料初稿を一度通読した段階で、詳細レビューとラボ実施はこれからです。

### Kubernetes

> Kubernetes は基礎教材の作成・講義と、主にオンプレミスの学習・検証環境を構築した経験があります。商用クラスタの設計・構築・運用経験はありません。過去に扱った構築方式やリソースの詳細は、提出前に本人確認して限定します。今回用意されたラボは未実施で、過去経験とは分けて扱います。

### OpenShift Virtualization / Airgap

> 実導入経験はありません。構成要素と設計論点を扱う資料初稿は一度通読しましたが、詳細レビューと検証はこれからです。現時点では技能として主張せず、レビュー後に説明できる範囲と未確認事項を記録します。

## 参画時の最初の確認事項

- 対象の OpenShift / Operator バージョンとサポート期限
- 導入方式、基盤、クラスタ規模、ネットワーク・ストレージ方式
- 自分の役割、変更権限、承認者、レビュー担当、エスカレーション経路
- 設計書、パラメータシート、試験仕様、既知課題、運用手順の所在
- 開発・検証・本番の差、利用可能な再現環境
- ログや構成情報を外部へ持ち出せる範囲と AI 利用規程
