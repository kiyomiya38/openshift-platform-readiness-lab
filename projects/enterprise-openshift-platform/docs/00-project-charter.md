## 1. 背景と目的

既存の社内Web/APIワークロードと一部VMを、運用・セキュリティ・変更管理の責任を明確にした共通OpenShift基盤へ段階的に収容します。

- 第1段階: x86_64ベアメタルへOpenShift Container Platformを導入する。
- 第2段階: OpenShift VirtualizationとMTVを用い、代表VM 3台の移行PoCを行う。
- KongとSysdig: 製品導入を確約せず、周辺製品として連携点と責任分界を設計する。
- 学習目的: 要件から設計、構築、試験、移行、運用引き継ぎへ追跡できる文書一式を作る。

## 3. スコープ概要

### 3.1 対象

- OCP 4.22.z（正確なzリリースは導入判定時に固定）
- Agent-based Installer、`platform: none`、Control Plane 3台、Worker 3台
- クラスタ外DNS、NTP、冗長LB、Proxy、外部CSIとの接続設計
- 認証、RBAC、SCC、証明書、Secret、監査の方針
- 監視、ログ、バックアップ、更新、障害・変更・容量管理
- 第2段階のOpenShift Virtualization／MTV PoC
- Kong／Sysdigの連携境界
- 設計書、パラメータ、手順、試験、移行、切り戻し、運用引き継ぎ、管理台帳

### 3.2 対象外

- 実機調達、実クラスタ構築、コマンド実行、性能測定
- 本番VM移行の承認、および全VMの移行
- アプリケーション内部、外部DB内部、Kong／Sysdig製品内部の詳細設計
- ROSA／AROの構築、OpenShift AI、Disconnected構成
- 実在組織のアドレス、認証情報、ライセンス契約

詳細は [スコープ・責任分界](03-scope-responsibility.md) を参照します。

## 6. ガバナンス

### 6.1 会議体（想定）

| 会議 | 頻度 | 目的 | 記録 |
| --- | --- | --- | --- |
| プロジェクト定例 | 週次 | 進捗、課題、依存関係 | 議事録、課題表 |
| 技術設計レビュー | 設計節目 | 設計判断・互換性・運用性 | 指摘表、ADR |
| 変更審査 | 変更ごと | 影響、手順、切り戻し | 変更申請 |
| Go/No-Go判定 | 構築・移行前 | 前提、試験、リスクの最終確認 | 判定記録 |

### 6.2 変更原則

1. 要件、設計値、製品版の変更は変更IDを採番する。
2. 影響する要件ID、設計ID、試験ID、手順を特定する。
3. 申請者と実施者だけで完結させず、レビュー・承認者を分ける。
4. 中断基準、切り戻し条件、確認結果を実施前に記載する。
5. 緊急変更も事後レビューと証跡補完を必須とする。
