# スキルギャップ分析

## この分析の前提

本書は v0.1 準備版です。全章の初回通読は行いましたが、詳細レビュー、公式資料確認、リポジトリ内ラボ、実機証跡の登録はいずれも未完了です。

「学習した内容」には、現在リポジトリへ配置されている**技術資料初稿の範囲**を記載します。初回通読は済んでいますが、本人が学習・理解・検証を完了したという意味ではありません。詳細レビュー後は、実施事実に応じて「未レビュー初稿」「概要理解」「教材・検証」「商用経験」のいずれかへ更新します。

| 優先度 | 判定基準 |
| --- | --- |
| A | 面談で重視され、基盤案件の初動に必要 |
| B | 中心技術を支え、案件テーマに応じて必要 |
| C | 周辺製品として概要と連携点を押さえる |
| 自主追加 | 面談の明示要求ではないが、将来の理解を補う |

## 1. 基盤案件の進め方

### 現時点

OpenShift 基盤案件を要件整理から運用引き継ぎまで担当した商用経験はありません。講師・教材作成・学習環境構築の経験を、基盤案件の各工程へどう転用できるかは本人確認が必要です。

### 不足している点

- 要件、制約、未確定事項を設計判断へ変換する経験
- 基本設計、詳細設計、パラメータ、手順、試験を相互に追跡する品質管理
- 承認、変更管理、切り戻し、レビュー指摘を含む実案件の進行
- アプリケーション、基盤、運用、セキュリティ等との調整経験

### 学習した内容

[基盤案件の進め方](05-infra-project-process.md) と各種 [テンプレート](../templates/) に、工程、成果物、品質ゲートの初稿があります。詳細レビューと記入演習は未実施です。

### 今後の検証予定

小規模な想定環境について、要求一覧、基本設計、パラメータ、構築手順、試験仕様、切り戻しを一組作成します。成果物間の ID 対応、レビュー記録、未確定事項を第三者に確認してもらいます。

### 面談での説明方針

商用 OpenShift の設計経験とは表現しません。「基盤案件の成果物と確認観点を資料初稿として準備しており、今後、想定条件で記入・レビューする計画です」と説明します。

### 現時点

### 不足している点

### 今後の検証予定

### 面談での説明方針

「商用障害対応ではなく、教材・講義上のエラー整理が過去経験です。現在はラボ用の調査資料初稿を準備しており、実施証跡はまだありません」と説明します。
