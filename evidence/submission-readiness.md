2. 事前申告された経験と、記載された環境・操作・成果物を照合していない。
3. 技術記述を対象バージョンの公式資料で確認した記録がない。
4. リポジトリ内ラボを本人が実施していない。
5. 実機のコマンド、期待値、実測値、判断を示す証跡がない。
6. 自己説明と第三者レビューを実施していない。
7. 組織の生成 AI 利用・外部共有方針を確認していない。

## 必須ゲート A: 目的と位置づけ

- [ ] 自主的な準備資料であり、正式な提出依頼に基づく成果物ではないことを明記した。
- [ ] 今後の面談・参画機会が未定であることを明記した。
- [ ] 特定案件への参画、契約、役割を確約していない。
- [ ] v0.1 準備版から提出候補版へ版を更新した。

## 必須ゲート B: 本人レビュー

- [ ] README と learning-report を本人が全文確認した。
- [ ] docs/01、02、03 の要求、現在地、ギャップを本人が確認した。
- [ ] 技術章の断定、誤り、古いバージョン情報を本人が確認した。
- [ ] 本人の過去経験と一致しない記述を削除または修正した。
- [ ] 不明点を推測で埋めず、「要確認」として残した。

## 必須ゲート C: 経験境界

- [ ] 商用 OpenShift / Kubernetes の設計・構築・運用経験がないことを明記した。
- [ ] 教材・検証、概要理解、未経験、未レビュー初稿を区別した。
- [ ] 教材・講義上のトラブル整理を商用障害対応と表現していない。
- [ ] 「できます」「一人で対応可能」等の未実証表現がない。
- [ ] 自主追加領域を面談側の明示要求として表現していない。

## 必須ゲート D: 技術的な裏付け

- [ ] 対象製品・Operator のバージョンを特定した。
- [ ] 主要な技術記述を公式資料で確認し、確認日を記録した。
- [ ] 外部リンク、内部リンク、Markdown、YAML、Mermaid を再確認した。
- [ ] サンプル値が実在の顧客情報・秘密情報でないことを確認した。
- [ ] 実機確認がない主張を「検証済み」としていない。

## 必須ゲート E: 学習・検証証跡

- [ ] [learning-log.md](learning-log.md) に本人レビューと学習結果がある。

- [ ] 失敗、未解決事項、第三者指摘を削除せず記録した。

## 推奨ゲート: 読みやすさと再現性

- [ ] 表や図が本文と矛盾していない。
- [ ] 第三者が同じ手順を安全に再現できる。
