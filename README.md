# OpenShift基盤 実務成果物リーディングガイド

このリポジトリは、インフラストラクチャーの実務経験があり、OpenShiftは未経験のエンジニアを対象とした個人学習用教材です。架空のOpenShift 4.22基盤導入案件で使われる成果物例を、要求整理から運用まで工程順に読み解きます。

教材の目的は、製品機能を暗記することではありません。「どの入力から、何を判断し、どの成果物へ記録し、次工程へ何を引き渡すか」を理解することです。設問に回答する形式ではなく、実務成果物の記載内容と文書間のつながりを読み解きます。

## 対象者

- サーバー、ネットワーク、ストレージなどのインフラ実務経験がある
- Linux、TCP/IP、DNS、ロードバランサーの基本用語を理解している
- OpenShift案件の要求整理、設計、構築、試験、障害調査、移行、運用を一連で学びたい
- 実機を用意せず、一般公開可能な架空成果物を使って机上学習したい

Kubernetes自体が初めての場合も読み進められますが、用語で止まったときは[技術参考資料](reference/technical/)を併読してください。

## この教材で扱う範囲

- OpenShift Container Platform 4.22のオンプレミス基盤導入
- 要件定義、前提・制約、責任分界、トレーサビリティ
- 基本設計、詳細設計、パラメータ、構築手順
- DNS、NTP、Load Balancer、Proxy、Firewall、Storage、監視、バックアップ
- RHEL外部サービスとAnsibleによる構成管理
- クラスタ構築後のワークロード用Kubernetes/OpenShiftリソース
- 試験計画、結果管理、障害切り分け、運用引き継ぎ
- OpenShift Virtualization、KVM/QEMU/KubeVirt、MTVによるVM移行
- ROSA、ARO、Disconnected環境、Kong、Sysdig、OpenShift AIの関連領域

実際の製品操作、実環境へのインストール、性能測定、障害注入は扱いません。成果物中のコマンドや設定値は学習用の例であり、対象環境の承認・設計・バージョン確認なしに実行できる手順ではありません。

## 中心となる成果物例

[架空エンタープライズOpenShift基盤導入プロジェクト](projects/enterprise-openshift-platform/README.md)には、実務で関係する文書と実装資料をまとめています。

```text
projects/enterprise-openshift-platform/
├─ SCENARIO.md     架空案件で共通使用する前提
├─ docs/           プロジェクト文書 00〜24
├─ install/        Installer、DNS、LB、NTPの入力例
├─ ansible/        RHEL外部サービスの構成管理例
├─ manifests/      サンプルワークロードのManifest
├─ diagrams/       構成、通信、責任分界、構築、移行の図
└─ evidence/       この架空案件に固有のレビュー・確認記録
```

成果物は「完成した正解」ではなく、TBD、前提、停止条件、未実行結果を含むレビュー用ドラフトです。実務では環境・契約・組織標準・サポート条件に合わせて更新し、権限者の承認を受けます。

## 記録の扱い

[evidence/](evidence/)には、作業記録、設計レビュー、一次資料確認、静的検証、試験証跡、インシデントの汎用記録様式を置いています。事実と予定を混同しないため、未実施の項目は`NOT RUN`または`未実施`のまま扱います。

## 公開・安全上の前提

- 成果物例の案件、組織、人物、ホスト名、アドレス、計画日付はすべて架空です。
- 実在顧客の情報、認証情報、ライセンス情報、内部URL、実ログを追加しません。
- Secretは値を記録せず、保管場所、管理者、更新方法、確認状態だけを記録します。
- 公式資料は公開URLを参照し、製品バージョンと閲覧日を記録します。
- 実行結果を推測で埋めません。例示値、期待値、実測値を明確に分離します。
