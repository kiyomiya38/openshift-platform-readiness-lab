# openshift-platform-readiness-evidence

本リポジトリは、OpenShift / Kubernetes / OpenShift Virtualization 関連の面談内容を踏まえ、必要とされた技術領域を整理し、現時点の経験範囲・不足領域・技術資料初稿・今後の検証計画をまとめたものです。

商用 OpenShift 構築経験を示すものではありません。現時点では、面談内容に基づくキャッチアップ計画と技術資料の**準備版**です。本人による全章の初回通読は完了しましたが、詳細理解、公式資料での確認、リポジトリ内ラボの実施はまだ完了していません。

| --- | --- |

| 架空の基盤導入プロジェクト | AI 支援ドラフト作成済み。本人学習は未着手 |
| リポジトリ内ラボ | 未実施 |

> [!IMPORTANT]
> 本文の初稿作成には生成 AI の支援を利用しています。AI が生成した文章やサンプルは、それ自体では本人の技能・知識・経験の証明になりません。本人が内容をレビューし、一次資料で裏付け、必要な実機検証と自己説明を行った項目だけを証跡として扱います。

## 1. リポジトリの目的

- 前回面談で共有された期待事項を匿名化して技術要件へ整理する。
- 商用経験、過去の教材・検証経験、概要理解、未経験を分けて現在地を示す。
- 不足領域を明確にし、優先順位を付けたキャッチアップ計画を作る。
- 設計・構築・試験・障害調査で確認すべき観点を技術資料初稿として準備する。
- 本人レビューと検証の結果を、再現可能な証跡として段階的に蓄積する。

特定案件への参画や採用を前提とした資料ではなく、今後の対話に備えて技能・知識を判断いただくための自主的な準備資料です。

本資料は、共有先から正式な提出依頼を受けて作成した成果物ではありません。自主的な共有を想定して準備していますが、今後あらためて面談または参画検討の機会があるかは未定です。

## 2. 本資料の位置づけ

このリポジトリは、次の三つを分けて管理します。

1. **要求整理**: 面談で明示された期待事項を匿名化した要約
2. **技術資料初稿**: 学習対象を体系化した、生成 AI 支援によるドラフト
3. **証跡**: 本人がレビュー・確認・実施した事実を記録する領域

現在は 1 と 2 を準備し、全章を一度通読した段階です。通読だけでは理解・検証の証跡にならないため、「学習済み」「検証済み」「対応可能」とは判定していません。全体の報告は [learning-report.md](learning-report.md)、証跡の扱いは [evidence/README.md](evidence/README.md) にまとめています。

## 3. 面談内容から抽出した主要技術領域

面談の生の発言、個人名、組織名、案件情報は掲載せず、次の期待事項へ要約しています。

| 区分 | 技術・能力領域 | 位置づけ |
| --- | --- | --- |
| 中心領域 | OpenShift、OpenShift Virtualization | プラットフォームと VM 移行の理解対象 |
| 関連基盤 | Kubernetes、RHEL、Ansible | 基礎、運用、自動化を支える領域 |
| クラウド | ROSA、ARO | クラウドサービスと責任分界の理解対象 |
| 周辺製品 | Kong、Sysdig | Gateway、監視・セキュリティの関連領域 |
| 案件遂行 | 要件整理、設計、構築、試験、移行、運用引き継ぎ | 操作知識とは別に求められる基盤案件の進め方 |
| 行動特性 | 未知技術・障害の自走調査、試行錯誤、報告 | 特に重視された評価観点 |
| 情報管理 | AI 利用時の機密情報保護と一次資料確認 | 調査時に守るべきガバナンス |

詳細は [docs/01-meeting-requirements-summary.md](docs/01-meeting-requirements-summary.md) を参照してください。

OpenShift AI、Airgap / Disconnected Install、KVM / QEMU / KubeVirt や MTV の詳細は、面談で明示された中心要求と区別し、将来の案件テーマを見据えた**自主追加領域**として扱います。OpenShift Virtualization と VM 移行そのものは明示領域ですが、その実装内部の詳細まで要求されたとは解釈していません。

## 5. 学習・整理した技術領域

現時点で「学習完了」を示す領域はありません。以下について、今後レビューするための技術資料初稿を配置しています。

- OpenShift の基本設計、固有リソース、Operator ベースの管理
- OpenShift Virtualization、仮想化レイヤー、VM 移行観点
- ROSA / ARO とオンプレミス OCP の責任分界
- Kubernetes / OpenShift の障害調査
- RHEL / Linux、Ansible、自動化
- ネットワーク、ストレージ、監視、ログ、バックアップ
- Kong、Sysdig、AI 利用ガバナンス
- 自主追加領域としての Airgap / Disconnected Install、OpenShift AI
- 設計書、試験仕様書、移行計画、障害報告のテンプレート

「初稿が存在すること」と「本人が理解・説明・再現できること」は分けて評価します。

## 6. 今後の検証予定

1. 初回通読した各章を再読し、要点、誤り、不明点、自分の経験との差分を記録する。
2. 対象バージョンを決め、公式資料で技術記述を確認する。
3. 破棄可能な環境でラボを実行し、環境、コマンド、期待値、実測値を残す。
4. 結果を見ずに手順と判断理由を再説明し、再現性を確認する。
5. 設計・試験テンプレートへ想定条件を記入し、第三者レビューを受ける。
6. 経験ラベルと提出可否を証跡に基づいて更新する。

30 日の計画は [docs/04-learning-roadmap.md](docs/04-learning-roadmap.md)、記録様式は [evidence/learning-log.md](evidence/learning-log.md) と [evidence/verification-record.md](evidence/verification-record.md) を使用します。

初回通読後の次の演習として、架空の要件から設計・構築・試験・移行・運用文書を連続して読む [エンタープライズ OpenShift 基盤導入プロジェクト](projects/enterprise-openshift-platform/README.md) を用意しています。実機がない段階では机上設計と静的確認までを行い、実測結果は記録しません。

## 8. 学習時の読み方

学習時は、ファイルを探し回らず、次の順番で進めます。`docs/` の先頭2桁は、本文を初めて読む順番と一致しています。

1. 本 README で目的、現在状態、経験境界を確認する。
2. [learning-report.md](learning-report.md) で要求と計画の対応を確認する。
3. [docs/00-repository-guide.md](docs/00-repository-guide.md) を読む。
4. `docs/01` から `docs/27` まで番号順に読む。
5. [docs/04-learning-roadmap.md](docs/04-learning-roadmap.md) で指定された時点に、対応する `labs/` の演習を行う。
6. 全章の初回通読後は、[架空の基盤導入プロジェクト](projects/enterprise-openshift-platform/README.md) を番号順に進める。
7. 実際に行った内容だけを [evidence/](evidence/) に記録する。

> `docs/27` は用語集です。順番では最後ですが、途中で分からない用語が出たときにも参照できます。

## 9. 注意事項

- 面談の発言を直接引用せず、個人名、組織名、顧客名、業界、案件規模、内部事情を掲載しません。
- 特定案件の存在、参画、役割、将来の契約を確約する資料ではありません。
- サンプル手順は特定環境へそのまま適用せず、対象バージョン、権限、影響、退避、切り戻しを確認します。
- 顧客情報、IP アドレス、ホスト名、ログ、認証情報、秘密鍵を外部 AI や本リポジトリへ投入しません。
- AI 出力は誤りを含む可能性があるため、公式資料と実機結果を優先します。

## 10. 商用経験との線引き

| ラベル | 判定条件 | 本資料での表現 |
| --- | --- | --- |
| 商用経験 | 実案件で責任範囲を持ち、承認・変更管理・レビュー下で実施 | 対象、役割、期間、成果を事実で限定する |
| 教材・検証 | 本人が研修・個人ラボ等で操作し、結果を記録 | 環境、実施内容、制約を明記する |
| 概要理解 | 本人が目的と主要論点を自分の言葉で説明できる | 実施経験がないことを併記する |
| 未経験 | 本人による操作・設計・導入がない | 未経験と明記し、確認方法を示す |
| 未レビュー初稿 | AI 支援等で文章はあるが、本人確認・裏付けがない | 技能証明や学習成果に数えない |

現時点の本リポジトリは全章の初回通読まで完了していますが、詳細レビュー・裏付け確認前の **技術資料初稿** として扱います。新しい架空プロジェクトは本人学習前です。証跡への昇格条件と外部提出判定は [evidence/](evidence/) で管理します。
